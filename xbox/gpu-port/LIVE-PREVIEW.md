# Живой диагностический просмотр — 22 октября 2026

Реальные кадры `CaptureGuestOutput` передаются из отдельного shell runtime в Android PreviewActivity. Подтверждён экран планшета с кадром №35, 1280×720 (work/startup/live-preview-screen.png). Это CPU readback preview, не Surface/swapchain и не оценка FPS самой игры.

## Реализация

- Опциональный ME_GUEST_PREVIEW=1 включает native listener строго 127.0.0.1:38761. Нет удалённого listener, игровых команд или канала ввода. Другие локальные приложения с сетью потенциально могут подключиться; транспорт только для диагностики.
- Протокол: четыре BE uint32 magic MEF1, width, height, RGBA byte length; затем tightly packed RGBA. Dimensions 1..4096, length проверяется до выделения Bitmap.
- Capture worker: интервал минимум100мс при клиенте (ранее500мс), старый PPM dump раз в3с. Реальная частота может быть ниже; это не заявленные2FPS игры. Частота capture отделена от vblank.
- send с таймаутом500мс и MSG_NOSIGNAL; при обрыве клиент закрывается, возможен новый accept. Гостевой execution gate не удерживается во время capture/socket send.
- PreviewActivity читает в background thread, закрывает socket при onPause, повторяет соединение при отсутствии runtime. Кнопка «Живой просмотр игры (диагностика)» в MainActivity. Нужен INTERNET permission для loopback TCP.
- Ограничения: shell runtime всё ещё запускается через ADB; Activity не запускает/не приостанавливает игру. Управление игрой не подключено. Нет production cleanup GPU workers, прямого Surface, звукового решения или проверенных сохранений.
