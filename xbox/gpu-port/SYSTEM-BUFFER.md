# Системные GPU-метаданные и вход VdSwap

2026-10-21, Lenovo Y700 test device, запуск через ADB.

Исследован единственный вызов VdGetSystemCommandBuffer в игровом AOT. Он передаёт выходы на стеке, затем передаёт их VdSwap. Закреплённый RexGlue обнуляет 0x94 байта первого выхода, записывает BEEF0000/BEEF0001. Его VdSwap не разыменовывает эти маркеры: он формирует собственный PM4 swap packet. Маркеры не являются физическим системным буфером или подтверждением завершения GPU.

В --gpu-explore реализован строго ограниченный вариант для LR 82815008, с проверкой доступности и непересечения выходов, требованием готового GPU. В обычном режиме операция останавливается. Это диагностическая совместимость с RexGlue, не полная реализация Xbox-протокола.

На планшете игра дошла до VdSwap, LR 8281506C. Получены адрес команд BF8F1594, texture header 700FF370, writeback FFBF4008, metadata 700FF3A0, identifier BEEF0001. Эти параметры записаны до изменения команд. VdSwap пока намеренно останавливается с VdSwap_packet_generation_not_implemented. Сам вызов ещё не отправляет swap в GPU. Read/write первоначального ring остаются 25/25.

Следующий шаг: проверка texture fetch, виртуально-физический перевод frontbuffer, генерация пакетов на границе отдельного SDK TU без смешивания PPCContext ABI; затем проверка потребителя PM4_XE_SWAP и режима без presentation. Завершение system identifier остаётся отдельной нерешённой задачей.

242 существующих self-tests прошли; передача новых метаданных проверена игровым запуском. Журналы device-system-buffer-explore.log и device-system-buffer-self-test.log. Исходные игровые файлы и APK не изменялись.
