# Диагностический предел потоков

2026-10-22. Собственный предел loader увеличен с16до64thread records, включая main/GPU/audio. Это не реализация полного scheduler и не64одновременно протестированных native threads.

Все три места проверки capacity используют одну константу, initialize_thread проверяет index и прежний предел стека1МБ. Compile-time assertions подтверждают отсутствие пересечений крайнего слота63:

- PCR613F0000..613F2000 остаётся ниже TLS62000000.
- TLS/static/dynamic слот69E00000 с максимальным допустимым размером104000 остаётся ниже main stack70000000.
- Stack78E01000..78F01000 остаётся ниже GPU MMIO7FC80000; stride2МБ сохраняет промежутки.

На Y700 прошли556 self-tests (work/startup/thread-capacity-self-test.log, exit0). Реально отображены metadata/TLS/стек крайнего слота63, проверены PCR/self context, high/low/SP, доступность TLS и независимость последнего TLS slot от основного потока. После проверки тестовая запись удалена и main thread-local bindings восстановлены. Запуск64native threads этим тестом не заявляется.

Records завершённых потоков пока не переиспользуются. Поэтому64 — ограничение суммарно удерживаемых records, а не бесконечное создание/удаление потоков. Дальнейший lifetime/reuse остаётся открытым.
