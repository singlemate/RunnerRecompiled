# Kernel object waits и critical regions — 21 октября 2026

Реализованы KeEnterCriticalRegion/KeLeaveCriticalRegion как вложенное изменение guest KTHREAD.apc_disable_count (offset 0xB0): enter уменьшает, leave увеличивает до 0. Проверяется контекст, переполнение и unbalanced leave. Это НЕ mutex и не запрещает выполнение других guest threads. APC queue/insertion/delivery остаются unsupported; никаких APC callback не выдумывается. Count хранится в guest big-endian layout. Изученный pinned SDK использует этот же offset/направление счётчика.

KeInitializeEvent/SetEvent/ResetEvent/ClearEvent и KeWaitForSingleObject работают с embedded guest object, а не Nt handle. Состояние event хранится в его X_DISPATCH_HEADER в guest памяти: byte type 0/1, signal_state BE32 +4. Тип 0 — manual/notification, тип 1 — auto/synchronization (успешный wait потребляет сигнал). Это также распознаёт inline-initialized события игры, которые не проходили KeInitializeEvent import. Guest wait-list pointers/host addresses не записываются.

Wait поддерживает event и известный KTHREAD по адресу. Поддержаны NULL indefinite, zero timeout poll и negative relative до 60 s; positive absolute timeout/alertable/APC и другие object types явно отвергаются. Невыполненный wait отдаёт execution_gate через condition_variable и снова получает перед возвратом. KeSetEvent уведомляет state_changed. Set(wait=true) с atomic wait handoff не поддержан. Priority increment не меняет Android scheduling. Существующие Nt handle-based waits сохранены отдельно. Inline producer, который обходит KeSetEvent и пишет signal_state напрямую, сам по себе не гарантирует CV wakeup — это ограничение текущего event model, не общее fault/watch решение.

Новая игровая остановка critical_section_unwritable оказалась IAT export VdHSIOCalibrationLock (прочитана по 0x82000780). Он теперь указывает на реальную shared RTL critical section по 0x60003080. Инициализирована в unlocked state, type 1, packed spin-count 40 (округление SDK 10000/256), lock_count=-1, recursion/owner=0. Использует существующие полноценные Rtl lock/try/leave и общую guest ownership модель. Объект размещён в metadata virtual region, а не physical heap; MmGetPhysicalAddress для него пока не поддержан. Остальные неизвестные exports не разыменовываются как фиктивные объекты.

Y700: 242/242 loader checks. Дополнительные 14 проверяют nesting -2/-1/0, auto reset и poll, сохранение manual signal на двух waits, reset previous state, relative timeout, настоящий cross-thread signal через KeSetEvent (wait освобождает gate), wait terminated KTHREAD и shared HSIO lock initialization/acquire/release. Проверки используют новые настоящие imports, не имитируют ожидание заранее возвращённым SUCCESS.
