# Диагностика опроса и переключения потоков

2026-10-21, Y700 Gen4 / test device.

## Проверенный результат

- Пересобраны все 300 игровых TU с -O1 (137.1 с, archive_exit=0). Старый -O0 архив сохранён приватно как work/xbox-game-private/libmirrorsedge_ppc_mmio_o0.a. Ускорение всей игры не измерено; один -O1 не устранил остановку.
- Добавлены host PC/module offset, guest LR/CTR/регистры и четыре снимка через 5 секунд. Timeout теперь завершается отдельно (44), не маркируется execution_fault.
- Без экспериментального переключения снимки повторяются вокруг 822DB900 → 822DBB08 → косвенного вызова 8238E850. Это опрос объекта; полный смысл класса ещё не восстановлен.
- Отдельный --gpu-explore-poll-yield оборачивает только косвенный вызов 8238E850: вызывает оригинал, сохраняет его результат, при нулевом результате каждые 256 вызовов отпускает execution_gate на 1 мс. Регистры/буферы/результаты не подменяются. Это диагностическая точка переключения, не полноценная вытесняющая многозадачность. Обычный --gpu-explore её не включает.
- С переключением файловый рабочий поток получает выполнение и проходит дальше: открывает Core.xxx, устанавливает позицию 0 и читает все 65536 байт. В одном прогоне следующий запрос — Engine.xxx.
- Принят NO_INTERMEDIATE_BUFFERING (0x8) для staged read-only backend без хостового O_DIRECT; полная Xbox cache/DMA/alignment семантика не реализована.
- Реализован NtSetInformationFile class14: проверенная BE64 позиция, отрицательное смещение отклоняется, содержимое файла не меняется. Остальные классы явно останавливаются.
- Engine.xxx (2392064 байта) извлечён из своей копии и помещён на устройство. Последний прогон после staging не подтвердил его открытие: раньше возникло другое ожидание, main PC в libc, LR 822DC8CC. Нельзя утверждать, что Engine уже прочитан.

## Проверки и следующий шаг

358/358 self-tests на планшете. Новые проверки: временный файл, seek, чтение от текущей позиции и отклонение отрицательной позиции без изменения состояния.

Логи: device-stop-snapshot.log, device-o1-samples.log, device-poll-yield-explore.log, device-core-position-explore.log, device-engine-explore.log, device-position-self-test.log.

Далее нужны снимки остальных гостевых потоков: main в libc может ждать execution_gate, пока другой поток выполняет цикл. По одному main stack причина не установлена. Общий scheduler остаётся незавершённым; галочку готовности загрузки/меню не ставим.
