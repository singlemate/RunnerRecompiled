# EDRAM / HSIO: диагностический проход на Y700

**Уточнение 2026-10-22:** описанное ниже HSIO=false приводило к отключению публикации команд в гостевом драйвере. Текущая реализация сообщает готовность после успешного Vulkan setup. Причина и проверки: [GPU-SUBMISSION.md](GPU-SUBMISSION.md). Ниже сохранён исторический результат первого прохода.

2026-10-21. Сборка установлена через ADB; запуск выполнен на test device.

В режиме `--gpu-explore` добавлены ограниченные обработчики VdRetrainEDRAMWorker и VdRetrainEDRAM для наблюдённых аргументов. Они возвращают ноль, как закреплённая версия RexGlue, не выполняют аппаратную тренировку и не меняют выходные буферы. В исследованном месте вызова ноль выбирает путь без генерации команд и повторной тренировки. Это диагностическое допущение совместимости, а не реализация оборудования Xbox.

VdIsHSIOTrainingSucceeded возвращает false: на Android тренировка HSIO Xbox не выполнялась. Перекомпилированный игровой код записывает этот результат и продолжает инициализацию. Обработчики требуют готового GPU и явного режима исследования; обычный запуск сохраняет прежнюю остановку на ненулевом system GPU identifier. Протокол завершения identifier по-прежнему не реализован.

Подтверждено журналом device-hsio-explore.log:
- настоящий Vulkan backend и игровой ring инициализированы;
- начальные команды обработаны, write_index/read_index = 25/25;
- после HSIO игра выделяет дополнительную физическую память;
- следующая контролируемая остановка: MmSetAddressProtect, LR 82381548, адрес BF540000;
- игровой кадр, draw и нормальное завершение не подтверждены.

После обновления пройдены 242 существующие проверки памяти и синхронизации на планшете (device-hsio-self-test.log). Эти проверки не доказывают корректность диагностических допущений EDRAM для всей игры.

SHA256 установленного загрузчика: 01b6f115a9f537d2f655286ae2cd49ce02ceb98b08023c1746e0de6ae65bfe77.
