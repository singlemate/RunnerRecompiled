# Поток доставки прерываний — 21 октября 2026

Добавлен MeGpuInterruptWorker: реальный std::thread, FIFO до 64 ожидающих запросов, запрет submit до запуска/после остановки, проверка address alignment/CPU, drain и join. Исключение сохраняется как exception_ptr, оставшаяся очередь сбрасывается, новые запросы отвергаются. Управление start/stop/join выполняет один владелец, join и уничтожение — только вне worker и без execution_gate. Это поток доставки callbacks, НЕ command processor и не декодер PM4.

В loader dispatch_gpu_interrupt_locked использует только собственный XenonRecomp PPCContext. Callback проверяется по AOT function table; стек и PCR проверяются до входа. Для worker в тесте выделены отдельные stack/PCR/KTHREAD/TLS. Вызов выполняется под execution_gate: r3=source, r4=argument, CPU по умолчанию 2, PCR TLS pointer временно 0, LR sentinel 0xBCBCBCBC, stack padding 176 bytes (как в изученном исходнике SDK). RAII возвращает TLS pointer, stack/LR, CPU bytes, host FP CSR и thread-local привязки даже при исключении. Остальные регистры принадлежат выделенному контексту, не копируются между ABI.

В SDK GraphicsSystem введён SetExternalInterruptDispatcher: принимающий callback address/userdata/source/CPU обработчик может передать запрос в эту очередь. Пустой обработчик сохраняет legacy FunctionDispatcher-путь. Setter вызывается до GPU workers; runtime-замена без синхронизации не поддержана. В loader настоящий GraphicsSystem пока НЕ создан и этот hook к нему НЕ привязан. Асинхронная доставка и ordering реального CP/vblank ещё не проверены. APC, точное DPC/IRQL поведение, преэмпция и запертый guest spin loop не реализованы.

Y700: 169/169 loader checks (раньше 148). Проверены FIFO-доставка двух запросов через отдельный host thread, аргументы тестового callback, нулевой TLS внутри и восстановленный снаружи, CPU/PCR/KTHREAD, выполнение настоящей AOT-функции sub_82230088 с искусственным адресом данных, неподходящие запросы, drain/join, отказ после stop и восстановление после callback exception. Синтетический callback временно установлен в отдельный slot function table только self-test и затем удалён. Реальные игровые GPU-прерывания не генерировались.

Повторный настоящий старт новой binary на планшете завершился ожидаемой диагностикой VdInitializeEngines_requires_xenos_backend (42), GPU по-прежнему false. Все 80 GPU/helper объектов пересобраны; отдельные shader/bootstrap/host executables заново слинкованы, в этом этапе они на устройстве не запускались. Полная строгая GPU link всё ещё не проходит: 12 external symbols, потому что legacy runtime branches пока сохранены. Cumulative rexglue-android-runtime.patch обновлён; старые патчи поверх него не применять.

Дальнейшие обязательные части: physical invalidation/write-watch, выбор внешнего worker для CommandProcessor/VSync, подключение GraphicsSystem к адаптерам, проверка общей синхронизации и только затем попытка VdInitializeEngines. Изображения игры пока нет. APK не менялся.
