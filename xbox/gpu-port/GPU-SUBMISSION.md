# Публикация GPU-команд и HSIO compatibility

2026-10-22. Наблюдение вместо вывода о готовности по одному VdSwap.

## Найденная причина

В gpu-submission-game.log добавлено наблюдение до/после оригинальной sub_828138E0 и после генерации VdSwap. Wrapper вызывает оригинал без подмены результатов/контекста; снимки только для первых8вызовов и степеней2. Проверяются адреса каждого читаемого поля. 614 regression checks с этим наблюдением прошли на Y700.

После начальных WPTR31/RPTR31 guest command cursors продолжают изменяться, но MMIO WPTR больше не публикуется. Снимки показывают flags00160400: byte device+10941 содержит bit2, field21532=0.

Причина прослежена по оригинальному гостевому пути:

- В startup 828188FC результат VdIsHSIOTrainingSucceeded инвертируется и записывается в global830F5D18.
- При ненулевом global sub_82813B40 устанавливает bit2 в device+10941.
- При установленном bit2 sub_82813450 выбирает отдельную ветку. При field21532=0 она возвращается без записи CP_RB_WPTR. Обычная ветка содержит реальную MMIO store7FC80714.

Предыдущая интерпретация HSIO=false как «на Android нет аппаратной калибровки Xbox» была неверна для runtime: она отключала публикацию команд в игре. В виртуальном GPU контракт этого запроса должен отражать готовность совместимого backend. Закреплённый RexGlue src/kernel/xboxkrnl/xboxkrnl_video.cpp также возвращает1.

## Исправление

В разрешённом диагностическом режиме запрос допускается только после успешного SetupExternalGpu (game_gpu_ready). Возвращается1 с явной диагностикой hardware_training=false/backend_ready=true/compatibility_result=1. Физическая калибровка Xbox не выполняется. GPU read pointers, identifier и завершения не подделываются; гостевые флаги напрямую не патчатся.

## Проверки и игровой результат

Контрольный прогон gpu-submission-game.log завершился по240с/exit44: cursors меняются, WPTR/RPTR остаются31/31. Исправление HSIO прошло616self-tests и изменило игровой путь: gpu-hsio-ready-game.log остановился42 на data import VdGpuClockInMHz, IAT82000770/ordinal448, LR828226A4.

VdGpuClockInMHz привязан к BE32ячейке60003120 со значением500, как в pinned SDK. Это фиксированный гостевой Xenos clock profile, не измерение частоты Adreno. checked_span допускает чтение ячейки и запрещает запись; исходный host page остаётся metadata RW, аппаратная защита отдельных4байт не заявляется. Физическое адресование этой metadata ячейки не реализовано. Значение и IAT binding проверены;618self-tests.

Следующий RtlFillMemoryUlong реализован для выровненного, кратного4объёма до существующего1МиБлимита checked_span. Заполняет BE32шаблоном, void ABI сохраняет аргументы, нулевой объём не обращается к памяти. Проверены неоднородный шаблон, bytes, sentinels, zero size;623checks. Игра прошла реальное заполнение800байт.

VdInitializeScalerCommandBuffer ограничен фактически наблюдавшимся тождественным720pпрофилем: source/output XY=0, все WH=050002D0, count200, проверенный выходной буфер. Пакетная упаковка WH уточнена по игровому вызову; исходный комментарий SDK о порядке halfwords не использован как доказательство. Выдаются200PM4type2NOP (BE80000000), возвращается200words, как no-op scaler compatibility SDK; масштабирование/фильтры Xbox не реализованы. Иные размеры/координаты явно останавливают probe.626checks прошли после уточнения упаковки (scaler-packed-self-test.log).

scaler-packed-game.log подтверждает прохождение вызова и новые MMIO WPTR34/37/40/43. В штатных publication windows до import stop достигнуты WPTR43/RPTR43; flags00140400 без прежнего bit2. Backend также вызвал PRESENT и сообщил NO PRESENTER. Это реальный путь обработки, но Android Surface/вывод не подключены. Следующая явная остановка42: VdPersistDisplay, LR82815458, r3=700FF388.

Следующий шаг: разобрать VdPersistDisplay и владение сохраняемой display memory. Закреплённый SDK выделяет служебный physical object вызовом heap->Alloc(64,32,...), записывает out pointer и возвращает1; считать контракт полностью выясненным по этому упрощённому коду нельзя. Не подставлять успешное сохранение дисплея без реализации и проверки срока жизни.
