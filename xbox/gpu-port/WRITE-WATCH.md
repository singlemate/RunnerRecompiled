# Software physical invalidation — 21 октября 2026

В MeRexGpuMemory вместо прежнего явного отказа реализованы регистрация/снятие invalidation callbacks и software page watches. Для каждого отслеживаемого 4 KiB физического блока хранится точная копия байтов. SynchronizePhysicalWrites сравнивает страницы без хеширования; изменённая страница снимается с наблюдения и вызывает callbacks с page-aligned диапазоном и exact=false. Повторная регистрация диапазона не заменяет уже существующий снимок: это не скрывает ещё не замеченную запись. Возвращаемые callback диапазоны для дополнительных unwatches не используются — соседние страницы сохраняются под наблюдением.

Сравнение не зависит от инструкций-производителей, поэтому замечает скалярные, SIMD, атомарные, memcpy/memset и raw-provider записи. Возможна избыточная invalidation после GPU-origin записей; это консервативное поведение, не точный fault-based write-watch. Изменение и возврат к прежним байтам до чтения GPU не требует invalidation. Никакой обработчик SIGSEGV для watch не устанавливается, guest aliases остаются RW.

Новый virtual hook GpuMemory::SynchronizePhysicalWrites вызван в настоящем Rex CommandProcessor перед primary buffer и в SharedMemory::RequestRanges до проверки GPU cache-valid flags. Legacy Memory оставляет hook пустым, потому что его собственные watches работают через fault handler. Внешний adapter переопределяет hook. Все вызовы adapter, CPU-производители и GPU-потребители ДОЛЖНЫ выполняться под execution_gate; текущая полная GPU-интеграция ещё не обеспечивает/не проверяет это, потому что CP не запущен. Независимый асинхронный CPU/GPU доступ этим методом не поддержан.

Перед unmap/free физической allocation map_physical вызывает InvalidateReleasedRange: callbacks получают уведомление, пока данные ещё доступны, snapshots удаляются до снятия mapping. Handle callbacks стабилен до уничтожения provider; unregister деактивирует его, повторный/чужой handle отвергается. При callback invocation снимается snapshot списка активных handles, что допускает reentrant register/unregister. Callback не должен уничтожать adapter. Data-provider callbacks по-прежнему явно не поддержаны, диапазоны вне выделенных страниц/512 MiB отвергаются. Необходимость удержания allocations до завершения GPU submissions сохраняется.

Цена prototype: 4096 дополнительных байтов на watched page плюс map overhead; каждое synchronize сканирует все watched pages. Это ориентированный на корректность вариант, производительность и FPS не измерялись. Не выдаётся за готовую когерентность асинхронного Vulkan renderer.

Новые проверки подтверждают чистую страницу без callback, одноразовое уведомление, повторное enable без потери записи, SIMD/atomic/raw write, диапазон двух страниц, unregister, неподдерживаемый provider, выход за allocation и настоящую physical_memory.free с уведомлением до unmap. 6/6 host packet-boundary checks также прошли.
