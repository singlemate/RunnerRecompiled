# Начальный поток, TLS и службы запуска — 21 октября 2026

Реальный ARM64 AOT-запуск оригинальной точки входа 829FAB98 повторно проверен на Lenovo Y700 Gen4 (TB322FC). Меню игры пока не достигнуто. Последний результат: runtime-result.json; полный журнал: device-runtime-final.log.

## Что теперь выполняется

- У начального потока есть минимальные KTHREAD/KPCR в гостевой памяти и r13, указатель текущего потока, границы стека, идентификатор и тип USER. Это не полноценный объект ядра или планировщик. DPC и другие потоки диагностируются как неподдержанные.
- TLS: 64 ячейки из настоящего XEX optional header 00020104, выделение, освобождение, чтение и запись значений. Статических данных TLS в этом XEX нет. Хранилище находится в гостевой памяти, указатели записаны в PCR и KTHREAD. Полный KPROCESS/его bitmap пока не моделируется; API использует собственный учёт свободных слотов. Исчерпание возвращает FFFFFFFF.
- Критические секции: инициализация, вход, выход и try-enter, включая рекурсивное владение единственным начальным потоком. Ожидающие потоки и спорный блокирующий вход останавливают диагностику. Проверка владельца не пропускается.
- NtFreeVirtualMemory: освобождение региона и декоммит с настоящим сбросом страниц через mmap в уже принадлежащем загрузчику диапазоне. После повторного commit память обнулена. Метаданные изменяются только после успешного системного вызова.
- Права XexCheckExecutablePrivilege читаются из SYSTEM_FLAGS оригинального XEX. Проверенный запрос бита 10 возвращает отсутствие права.
- RtlMultiByteToUnicodeN поддерживает проверенный ASCII-путь, длину буфера и необязательный выходной размер, записывает UTF-16 BE. Не-ASCII вызывает явную остановку: модель кодовой страницы ещё не выбрана.
- Холодный самостоятельный запуск не содержит данных от предыдущего title: XamLoaderGetLaunchDataSize записывает нулевой размер и возвращает ERROR_NOT_FOUND. ExLoadedCommandLine указывает на строку с именем загруженного default.xex в кавычках.
- KeQueryPerformanceFrequency и все пять единиц трансляции с mftb согласованы на 50 000 000 тиков в секунду. ARM cntvct пересчитывается по cntfrq; деление до умножения предотвращает переполнение при длительном uptime. Обновлён xenonrecomp-local.patch, пересобраны пять затронутых объектов и архив. Остальные объекты не изменялись.

В последнем реальном старте зарегистрированы 38 вызовов выделения виртуальной памяти, 16 освобождений, 26 инициализаций критических секций и три выделения TLS. Эти счётчики показывают выполнение стартового кода, но не доказывают корректность всей игры.

## Проверки

77 проверок прошли непосредственно в Android ARM64-процессе: рекурсивное владение и окончательный выход, отказ try-enter при другом владельце, исчерпание всех 64 слотов, повторное использование освобождённого TLS с нулевым значением, декоммит/повторный commit с нулевыми байтами, освобождение региона и измерение счётчика относительно CLOCK_MONOTONIC. Измерено 49 999 095 Гц (короткий тест около 20 мс). Журнал: device-self-test.log.

26 проверок менеджера памяти прошли отдельно на Windows, включая откат при ошибке callback, неверную базу release, границы декоммита, сохранение соседних страниц и повторное использование освобождённого адреса. Результат: memory-tests.log. Это логические проверки модели, а не проверка Windows как целевой платформы игры.

Сборка: `startup/build.ps1 -Workspace <корень рабочего каталога>`. Для self-test к обычным аргументам приватных секций и XEX-заголовка добавить `--self-test`. Собственный бинарник и все производные игры остаются в work и на пользовательском устройстве. APK не изменялся. Отдельные процессы проверки завершились.

## Следующая граница

FscSetCacheElementCount, LR 829FB27C. В исследуемом RexGlue xboxkrnl_io.cpp эта функция без реализации возвращает STATUS_SUCCESS; мы оставили именованную остановку. Нужен осмысленный договор файлового кэша вместе с будущей файловой системой game:, а не копирование безусловного успеха. Файловые дескрипторы, доступ к ресурсам, GPU, звук, планировщик и интеграция с APK пока отсутствуют. Четыре неподдержанные инструкции и два не полностью разрешённых switch-пути по-прежнему остаются ограничениями рекомпиляции.

Источники для контрактов: локальные RexGlue xboxkrnl_threading.cpp, xboxkrnl_rtl.cpp, xboxkrnl_modules.cpp, xboxkrnl_memory.cpp, xam_info.cpp, xthread.h/cpp и kernel_state.h/cpp на ранее закреплённом commit. Общий ABI с RexGlue не предполагается: загрузчик по-прежнему использует собственный контекст XenonRecomp.
