# Файловый кэш и события — 21 октября 2026

Реальный запуск на Y700 продолжен за прежнюю границу FscSetCacheElementCount. Это не реализация файлового кэша: среда явно возвращает STATUS_NOT_IMPLEMENTED (C0000002) и журналирует запрос 32 элементов, selector 0. Оригинальная обёртка игры проверяет отрицательный NTSTATUS и вызывает преобразование ошибки. Поддержан фактически достигнутый случай RtlNtStatusToDosError C0000002 → 1 по таблице Xbox в локальном RexGlue xboxkrnl_error.cpp. Другие неизвестные NTSTATUS вызывают именованную остановку. Игра сама продолжила исполнение после этой ветки, без изменения игрового кода или принудительного обхода условия.

Реализована собственная модель безымянных событий и импорты NtCreateEvent, NtSetEvent, NtClearEvent, NtWaitForSingleObjectEx, NtClose. Дескрипторы обозначают реальные записи состояния и после закрытия не переиспользуются. Тип 0 — manual reset, тип 1 — auto reset. Поддержаны немедленное успешное ожидание сигнализированного события и опрос с нулевым timeout; несигнализированное блокирующее ожидание вызывает остановку с требованием планировщика. Объектные атрибуты, именованные события, APC и многопоточная безопасность пока отсутствуют. NtClose сейчас обслуживает только события этого реестра; другие типы объектов ещё не создаются.

В фактическом запуске игра создала auto-reset event 00010000 с начальным состоянием 0, затем запросила ExCreateThread. Поток ещё НЕ создан: обработчик диагностический, не возвращает фиктивный handle или успех.

Параметры запроса:
- стек 32768 байт;
- XapiThreadStartup 82A09BE0;
- точка входа 823855B8;
- аргумент 1014D3E0;
- creation flags 0: немедленный старт;
- LR 82A01930.

Статическая проверка начальной функции показала, что она переходит в 823855E0, откуда вызывает методы через таблицу виртуальных функций объекта. Подменять этот поток одиночным вызовом из главного потока нельзя: момент возврата и последующие ожидания меняют поведение программы. Следующая работа — раздельные PPCContext, stack, PCR/KTHREAD и TLS, безопасные критические секции и реестр объектов, ожидание/сигнализация событий, создание и завершение настоящего рабочего потока. Текущий загрузчик остаётся строго однопоточным.

22 проверки модели событий прошли на Windows и те же 22 — отдельным ARM64-бинарником на самом Y700: auto/manual reset, повторная установка, предыдущий signal state, нулевой timeout, отсутствие готового результата при блокирующем ожидании, неверные и закрытые дескрипторы, отсутствие повторного использования handle, исчерпание лимита 4096 объектов. Эти тесты проверяют модель; в реальном коде игры на этом этапе фактически достигнуто только создание события. Журналы event-tests-host.log, event-tests-device.log и device-thread-request.log; сводка cache-events-result.json.

Файловые API и ресурсы игры ещё не достигнуты. Ранее извлечённый default.xex и оригинальный GOD-контейнер не изменялись; новые игровые файлы не извлекались и не загружались. APK не изменялся. Производный бинарник остаётся только в work и на личном планшете. Оба проверочных процесса завершились.
